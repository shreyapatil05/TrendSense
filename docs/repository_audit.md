# Repository audit

## Existing behaviour

The uploaded repository had config.py, an orchestrator, and eight numbered agent files. The scoring modules compiled, but the uploaded layout could not run because main imported normalized agents package paths that did not exist. Scout returned one list while one fallback branch expected two values. The decision display block reported only the final item's lifecycle/action window. Commercial naming was bridged by an alias but remained confusing.

The system already collected public signals, scored all 55 terms, classified lifecycle/authenticity, estimated industry and commercial relevance, produced decisions, and generated deterministic explanations. It handled partial Trends coverage more honestly than treating missing data as zero.

## Research blockers

There was no immutable observation schema, permanent forecast history, future outcome link, fixed ground-truth rule, temporal backtest, baseline implementation, experiment record, or quantitative accuracy output. Marketplace page presence was a proxy, not financial validation. Source coverage was vulnerable to Trends rate limits, RSS changes, Wikipedia gaps, and missing API keys. The components were functions in a sequential workflow, not autonomous AI agents.

## Preserved behaviour

All eight stage names, the 55-keyword portfolio, India scope, deterministic formulas, uncertainty handling, and INVEST/WAIT/AVOID policy are preserved. Synthetic integration testing ran all 55 trends through every stage.
